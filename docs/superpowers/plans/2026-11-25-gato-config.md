# Extensibility Task 5: `src/gato.config.ts` and `applyGatoConfig` (ADR-60)

Detailed contract for Task 5 of [the extensibility plan](2026-11-23-extensibility.md) (read its "Global constraints" and Task 5 first). Spec: §5.1 of [the extensibility design](../specs/2026-11-22-extensibility-design.md), decisions 4A and 12A.

Versions (next free at the time of writing): `kitFormat` 4 (`SUPPORTED_KIT_FORMATS` = `[1, 2, 3, 4]`), `gato-cli` 0.7.0, `create-gato-app` 0.3.4 with the pin `"gato-cli": "0.7.0"`, `core` 0.18.0 (0.19.0 if extensibility Task 3 merges first), `api-keys` 0.1.3, `audit-logs` 0.1.3.

## Signatures

### `src/shared/lib/modules/gato-config.ts` (new, `core`, client-safe: only type imports)

```ts
import type { OrgRole } from "@/shared/lib/auth/roles";
import type { ModuleDef } from "./define-module";

export interface GatoNavOverride { order?: number; hidden?: boolean }
export interface GatoModuleAccess { roles?: OrgRole[]; adminOnly?: boolean; multiOrgRoles?: OrgRole[] }
export interface GatoModuleConfig {
  enabled?: boolean;
  nav?: Record<string, GatoNavOverride>;
  access?: GatoModuleAccess;
}
export interface GatoConfig { modules?: Record<string, GatoModuleConfig> }

export const emptyGatoConfig: GatoConfig; // {}
export const UNDISABLEABLE_MODULES: readonly string[]; // ["auth", "organizations"]

export function defineGatoConfig(config: GatoConfig): GatoConfig; // returns its argument

export class GatoConfigError extends Error {
  name = "GatoConfigError";
  readonly problems: readonly string[];
  constructor(problems: readonly string[]);
}

export function gatoConfigProblems(modules: readonly ModuleDef[], config: GatoConfig): string[];
export function applyGatoConfig<T extends ModuleDef>(modules: readonly T[], config: GatoConfig): T[];

export interface ModuleEntry<T> { module: string; value: T }
export function enabledEntries<T>(entries: readonly ModuleEntry<T>[], config: GatoConfig): T[];
```

Rules:

- `gatoConfigProblems` walks `config.modules` in key order. For each key, in this order:
  - key not among `modules[].key` → `modules.<key>: unknown module: <key>` (nothing else checked for that key);
  - `enabled === false` and key in `UNDISABLEABLE_MODULES` → `modules.<key>.enabled: <key> cannot be disabled`;
  - each `nav` key that is not the `id` of one of that module's nav items → `modules.<key>.nav.<navId>: unknown nav id: <navId>`;
  - `access` present but sets none of `roles`, `adminOnly`, `multiOrgRoles` (all `undefined`) → `modules.<key>.access: access override sets none of roles, adminOnly, multiOrgRoles`.
- `GatoConfigError.message` = `"Invalid src/gato.config.ts:\n" + problems.map((p) => "- " + p).join("\n")`.
- `applyGatoConfig` throws `GatoConfigError` with every problem at once when `gatoConfigProblems` is not empty. Otherwise it returns a new array, same order, without modules whose config has `enabled: false`; for the rest:
  - a nav item whose `id` has an override with `hidden: true` is removed; an override with `order` sets `order` and keeps every other field of the item; items without an override are unchanged;
  - `access` **replaces the whole access policy**: the result has `roles`, `adminOnly` and `multiOrgRoles` taken from the override (a field the override does not set becomes `undefined`), every other module field unchanged. Reason: `adminOnly` wins over `roles` in `canAccessModule`, so a partial merge of `roles: ["owner"]` into `users` (`adminOnly: true`) would change nothing.
  - inputs are never mutated.
- `applyGatoConfig(mods, emptyGatoConfig)` deep-equals `mods`.
- `enabledEntries` returns the `value`s, in order, of entries whose `module` does not have `enabled: false` in the config. It does not validate (the `applyGatoConfig` call in the same generated file does).

### Generated registries (`packages/gato-cli/src/generate/registry.ts`, `index.ts`)

`renderRegistry(modules, locales, options?: { hasGatoConfig: boolean })`, default `{ hasGatoConfig: false }`. `generate` sets `hasGatoConfig` when `src/gato.config.ts` exists in the project.

Lines after the header, server file, for one module `demo` with module, env, auth, audit sink and both locales, `hasGatoConfig: true`:

```ts
// generated by GatoJS — do not edit. Run: npm run wa -- generate
import gatoConfig from "@/gato.config";
import type { Locale } from "@/i18n/config";
import { createEnv } from "@gatojs/env";
import { applyGatoConfig, enabledEntries } from "@/shared/lib/modules/gato-config";
import demoModule from "@/features/demo/module";
import { envSchema as demoEnvSchema } from "@/features/demo/env";
import { authPlugin as demoAuthPlugin } from "@/features/demo/auth";
import { auditSink as demoAuditSink } from "@/features/demo/audit-sink";

export const modules = applyGatoConfig([demoModule], gatoConfig);
export const moduleEnvSchemas = enabledEntries([{ module: "demo", value: demoEnvSchema }], gatoConfig);
export const authPlugins = enabledEntries([{ module: "demo", value: demoAuthPlugin }], gatoConfig);
export const auditSinks = enabledEntries([{ module: "demo", value: demoAuditSink }], gatoConfig);
export const env = createEnv(moduleEnvSchemas);

export type MessageLoader = { key: string; load: () => Promise<Record<string, unknown>> };

export const moduleMessages: Record<Locale, MessageLoader[]> = {
  pl: enabledEntries<MessageLoader>([
    { module: "demo", value: { key: "demo", load: () => import("@/features/demo/i18n/pl.json").then((m) => m.default) } },
  ], gatoConfig),
  en: enabledEntries<MessageLoader>([
    { module: "demo", value: { key: "demo", load: () => import("@/features/demo/i18n/en.json").then((m) => m.default) } },
  ], gatoConfig),
};
```

- `hasGatoConfig: false` → line 2 is `import { emptyGatoConfig as gatoConfig } from "@/shared/lib/modules/gato-config";`, everything else identical.
- An empty list stays as today: `export const <name>: never[] = [];`, and an empty locale stays `  <locale>: [],`.
- The helper import lists only the helpers used (`applyGatoConfig`, `enabledEntries`, alphabetical); when no helper is used, neither the helper import nor the config import (line 2) is emitted.
- Several entries in one list: `enabledEntries([{ module: "a", value: aEnvSchema }, { module: "b", value: bEnvSchema }], gatoConfig)`, joined by `, `, input order.

### Architecture

- `scripts/lib/architecture/client-imports.ts`: `CLIENT_ENTRY_FILES = ["src/gato.config.ts", "src/shared/lib/modules/gato-config.ts"]`; `checkClientBundles` reports server imports in these files (when they exist) as if they had `"use client"`.
- `scripts/lib/architecture/gato-config-keys.ts` (new): `findGatoConfigKeyProblems(root: string): Promise<string[]>`; `[]` when `<root>/src/gato.config.ts` is absent; otherwise imports its default export and the default exports of every `<root>/src/features/*/module.ts` (sorted by directory name) and returns `gatoConfigProblems(modules, config)`.
- `src/__tests__/architecture/gato-config-keys-exist.test.ts` (new): fixtures for the detection, and the repo itself reports `[]`.
- `src/__tests__/architecture/gato-nav-items-have-ids.test.ts` (new): skips when `kit/modules` is absent; for every client module whose `kit/modules/<key>.json` exists or that is a core module (`CORE_MODULE_KEYS`), every nav item has an `id` starting with `<key>.`, and nav ids are unique across the registry.

## Behaviours

1. `applyGatoConfig([dashboard, apiKeys], { modules: { "api-keys": { enabled: false } } })` → `[dashboard]`.
2. `{ modules: { auth: { enabled: false } } }` → throws `GatoConfigError`, message contains `modules.auth.enabled: auth cannot be disabled`; same for `organizations`. `{ auth: { enabled: true } }` passes.
3. `{ modules: { billing: {} } }` → throws, message contains `modules.billing: unknown module: billing`; `{ billing: {}, crm: {} }` → one error, `problems` equals `["modules.billing: unknown module: billing", "modules.crm: unknown module: crm"]`.
4. `{ dashboard: { nav: { "dashboard.home": { order: 5 } } } }` → the dashboard nav item equals the original with `order: 5` (href, labelKey, icon, id unchanged); `"dashboard.nope"` → throws with `modules.dashboard.nav.dashboard.nope: unknown nav id: dashboard.nope`.
5. `{ dashboard: { nav: { "dashboard.home": { hidden: true } } } }` → dashboard keeps its other fields and has `nav: []`.
6. `{ users: { access: { roles: ["owner"] } } }` → `getNavEntries` on the configured modules hides `/users` for org role `admin` (single and multi org), shows it for `owner`; `requireModuleAccess("users")` calls `notFound()` for `admin` and resolves for `owner`.
7. `{ users: { access: {} } }` → throws with `modules.users.access: access override sets none of roles, adminOnly, multiOrgRoles`.
8. `applyGatoConfig(mods, emptyGatoConfig)` deep-equals `mods`; the input array and its modules are not mutated by any config.
9. `requireModuleAccess("api-keys")` with `api-keys` disabled → `notFound()`; `getNavEntries` has no `/api-keys`.
10. `enabledEntries([{ module: "a", value: 1 }, { module: "b", value: 2 }], { modules: { a: { enabled: false } } })` → `[2]`; with `emptyGatoConfig` → `[1, 2]`; `{ a: { enabled: true } }` → `[1, 2]`.
11. The real generated registries apply the config: with `emptyGatoConfig` swapped (test-only mock of that one constant) for `{ modules: { "api-keys": { enabled: false }, "audit-logs": { enabled: false } } }`, `modules` and `clientModules` contain neither key, `moduleMessages.pl` and `.en` have no `api-keys`/`audit-logs` loader, `authPlugins` and `auditSinks` are empty, `moduleEnvSchemas` has 2 entries (encryption, uploads) instead of 3.
12. Generator: exact server and client output above, with and without `hasGatoConfig`; `generate` on a project with `src/gato.config.ts` writes `import gatoConfig from "@/gato.config";` as line 2 of both registries, without it the `emptyGatoConfig` import; a second `generate` changes nothing; adding or removing `src/gato.config.ts` and running `generate` again changes both registries.
13. `SUPPORTED_KIT_FORMATS` is `[1, 2, 3, 4]`; `kit/kit.json` `kitFormat` is 4. `create-gato-app` pins `gato-cli` `0.7.0`.
14. Architecture: `src/gato.config.ts` importing `@/shared/lib/prisma` (no `"use client"`) is reported as `src/gato.config.ts: @/shared/lib/prisma`; `findGatoConfigKeyProblems` on a fixture with a bad module key and a bad nav id returns both messages; a fixture without `src/gato.config.ts` returns `[]`. Every Gato module nav item has an id prefixed `<module>.`.

## Mutations to kill

- A disabled module kept in one of the lists (`modules`, `clientModules`, `authPlugins`, `auditSinks`, `moduleEnvSchemas`, `moduleMessages`, `authClientPlugins`).
- `auth` or `organizations` disable allowed; `enabled: true` on them rejected.
- An unknown module key or nav id ignored; only the first problem reported.
- A nav override replacing the whole item, or applied to the wrong item; `hidden` ignored.
- `access` merged instead of replacing (users stays visible to `admin`), or applied to the wrong module.
- Config applied to `clientModules` but not `modules`, or the reverse; generator emitting `emptyGatoConfig` when `src/gato.config.ts` exists, or the reverse.
- Input modules mutated.

## Follow-up from review: module key equals the feature directory

The generated `enabledEntries` lists name the owner by feature directory (`{ module: "<dir>", … }`), while `applyGatoConfig` matches `module.key`. D27 already requires `key` to equal the directory name, but nothing checked it; with `enabled: false` a mismatch would remove the module from `modules` and keep its auth plugin, audit sink, env schema and messages.

- `scripts/lib/architecture/gato-config-keys.ts`: `findModuleKeyMismatches(root: string): Promise<string[]>`; for every `<root>/src/features/<dir>/module.ts` (sorted by directory name) whose default export's `key` differs from `<dir>`, the message `src/features/<dir>/module.ts: key "<key>" differs from the directory name "<dir>"`; `[]` when `src/features` is absent.
- `src/__tests__/architecture/gato-config-keys-exist.test.ts`: fixtures (one matching, one mismatching module; no features directory) and the repo itself returns `[]`.

Behaviour 15: fixture `src/features/notes/module.ts` with `export default { key: "note", nav: [], routePrefixes: [] }` and `src/features/crm/module.ts` with key `crm` → `['src/features/notes/module.ts: key "note" differs from the directory name "notes"']`.

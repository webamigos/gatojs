# Workspace packages — implementation plan

**Goal:** `packages/` holds the GatoJS tools (`gato-cli`, `create-gato-app`, published to npm, never copied into projects) and project packages (`@gatojs/env`, `@gatojs/observability`, `@gatojs/crypto` with an `encryption` module, `@gatojs/eslint-config`, copied into projects like any Gato file).

**Spec:** [docs/superpowers/specs/2026-11-22-packages-design.md](../specs/2026-11-22-packages-design.md), accepted by Patryk on 2026-11-22 with the decisions in its section 7. Read it together with this plan.

**Execution:** Orca workers, one task per worker, each on its own branch from `main`, one PR per task. Order and parallelism:

```
Task 1 (infrastructure + tools move) ──┬── Task 2 (@gatojs/env) ──┬── Task 3 (@gatojs/observability)
                                       │                          └── Task 4 (@gatojs/crypto + encryption)
                                       ├── Task 6 (publish create-gato-app and gato-cli)
                                       └── (after 2–4) Task 5 (@gatojs/eslint-config)
```

Task 1 merges first. Tasks 3 and 4 start after Task 2 merges (they use its fragments). Task 6 starts after Task 1 and can run next to Task 2.

## Global constraints

- Rules in `CLAUDE.md`, `AGENTS.md` and `kit/CLAUDE.md` apply: no code comments except `// WHY:` (at most 3 lines) and tool directives; no `any`, nested ternaries or silent `catch {}`; Zod at external input; error class `name` as a string.
- New content (code, docs, commit messages, test titles) is English. Existing Polish docs are edited in their current language until the English migration.
- New decisions are ADR files in `docs/adrs/` (ADR-56 is reserved for Task 1). A non-obvious gotcha goes to `docs/lessons/`.
- Tests are written by the `test-writer` subagent before implementation; `.superpowers/phase` = `implement` in the worker's worktree during implementation; then the `test-reviewer` subagent runs `npm run test:mutation:task -- <files>` (and `--prefix packages/gato-cli` for CLI files) and `npm run test:mutation:gate`. Expected values are literals or come from the spec.
- Every Gato file change bumps the owning module's `version` in `kit/modules/<module>.json` (patch for fixes, minor for new behaviour), then `npm run wa -- kit sync && npm run wa -- generate`, committed, then `git diff --exit-code`. If `main` moved and the version collides, take the next free version.
- Gates before handing in: `npm run verify`, the CLI gate (`npm run verify --prefix packages/gato-cli` after Task 1), `npm run test:integration`, and `npm run test:e2e` when the task touches runtime code. e2e resets `wa_app_e2e`: ask the coordinator for Patryk's consent text before each run (lesson `prisma-refuses-a-database-reset-from-an-agent`), and use your own ports and containers (lesson `parallel-worktrees-need-their-own-ports-and-dirs`).
- Conventional Commits, lowercase subjects, body lines ≤ 100 characters, footer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push, PR or publish; the coordinator does that.
- Report: branch, commits, gate results with numbers, surviving mutants with classification, proposed `allowed` entries, anything unverified, gotchas.

### Task 1: Workspace infrastructure and the tools move (ADR-56)

**Branch:** `feat/packages-infrastructure`

**Files:**
- Move: `git mv kit/cli packages/gato-cli`. Start from branch `patrykomiotek/gato-cli` (publishable `gato-cli` 0.1.0, already reviewed) rebased onto `main`, so the move carries that work. `kit/create-gato-app` does not exist on `main` yet; Task 6 moves it.
- `packages/gato-cli`: drop its own `package-lock.json` (the root lockfile covers workspaces); keep its own Vitest, Stryker and `mutation-gate.json`; fix every path (`bundle.mjs` output `.wa/bin/wa.mjs`, `../../scripts/mutation-gate.ts`, fixtures).
- Root: `tsconfig.json` (stop excluding `packages/**`; tool packages keep their own `tsconfig`, project packages are covered by the root one), `eslint.config.mjs` (lint `packages/**` except build output; tool packages may keep their own config), `vitest.config.ts` (`test.projects`: `app` = today's include list, `packages` = `packages/*/src/**/*.test.ts` in the node environment, excluding tool packages, which run their own Vitest), `stryker.config.json` (`mutate` += `packages/*/src/**/*.ts`, minus tests and tool packages), `turbo.json`, `.lintstagedrc.json` (ESLint per workspace, as in Ragen's `lint-staged.config.mjs`).
- `Dockerfile`: a `# wa:workspaces:start` / `# wa:workspaces:end` region in the `deps` stage, after `COPY package.json package-lock.json ./` and before `RUN npm ci`.
- `packages/gato-cli/src/generate/targets.ts`: a region target for `Dockerfile` / `wa:workspaces` whose body lists `COPY packages/<name>/package.json ./packages/<name>/package.json` for every directory in `<project>/packages/*` that has a `package.json`, sorted by code point. Empty body when there is none.
- `kit/kit.json`: `kitOnly` += `packages/gato-cli/**` (and `packages/create-gato-app/**` ahead of Task 6); `.github/workflows/kit.yml`, `.github/dependabot.yml` (`/kit/cli` → `/packages/gato-cli`), `kit/CLAUDE.md`, `docs/16-cli-wa.md`, `docs/16b-rozwoj-kitu.md`, `docs/11-praca-z-kitem.md`: new paths.
- Architecture tests in `src/__tests__/architecture/` (detection functions in `scripts/lib/architecture/`):
  - `dockerfile-installs-every-workspace`: the `wa:workspaces` region lists exactly the `packages/*` directories with a `package.json` that exist on disk (Ragen's `a-scoped-dockerfile-installs-every-workspace-dep`);
  - `one-test-runner-for-every-workspace`: every project package's tests are matched by the root `packages` Vitest project, and project packages declare no `test` script; tool packages are listed explicitly as having their own runner;
  - `lint-staged-covers-every-workspace`: every workspace with source files is linted on commit.
- Manifest ownership: a manifest may own `packages/<name>/**` through `files`. A project package declares its npm dependencies in its own `package.json` (owned by that manifest); the root `package.json` and the manifests' `dependencies` stay for the app. This clarifies spec 3.3 and is written into ADR-56.
- Docs: ADR-56 `docs/adrs/56-workspace-packages-replace-d29.md` (supersedes D29 and the "no npm" part of D28: tool vs project packages, the Dockerfile region, no-build project packages, one root Vitest, ownership); index row; D29 and D28 get a status line pointing to ADR-56.
- `kit/modules/core.json`: minor bump (new region, Dockerfile change).

**Behaviours:**
- `workspacesBody` for a project with `packages/env/package.json` and `packages/observability/package.json` → `"COPY packages/env/package.json ./packages/env/package.json\nCOPY packages/observability/package.json ./packages/observability/package.json"`.
- No `packages/` directory → `""`; `packages/notes/` without `package.json` → ignored.
- `findDockerfileWorkspaceGaps(region, dirs)`: region lists `env`, disk has `env` and `crypto` → `["missing: crypto"]`; region lists `gone`, disk has none → `["extra: gone"]`.
- A project assembled with `wa create` (any module set) has no `packages/gato-cli`, its Dockerfile region is empty, and `docker build` passes (the `assemble` job).
- `npm run wa -- generate` in the kit is idempotent; `npm run verify --prefix packages/gato-cli` passes with the same test count as `kit/cli` before the move.

**Mutations to kill:** region body unsorted; a directory without `package.json` listed; `missing`/`extra` reversed; one-runner test accepting a project package with its own `test` script.

### Task 2: `@gatojs/env` replaces `src/shared/lib/env.ts`

**Branch:** `feat/package-env` (after Task 1)

**Files:**
- `packages/env/` (`@gatojs/env`, `private: true`, `exports: { ".": "./src/index.ts" }`, dependency `zod`), owned by `core` (`files` += `packages/env/**`).
- Content (spec 4.2): `coreEnvSchema`; `checkEnv`, `formatEnvReport`, `parseEnv`, `verifyEnvOnStartup` (today's behaviour from D48, unchanged messages); `createEnv(moduleSchemas)` (lazy, validated); fragments `httpUrl()`, `blankAsUndefined()`, `flag()`; rules `allOrNone(names, label)`, `requiredForProvider(providerVar, value, names)`.
- Generator: `src/modules.generated.ts` gains `export const env = createEnv(moduleEnvSchemas)`; a stable `src/env.ts` re-exports it (`@/env`). Every `@/shared/lib/env` import moves to `@/env`; `src/shared/lib/env.ts` is deleted. `next.config.ts` `transpilePackages: ["@gatojs/env"]`.
- `OTEL_EXPORTER_OTLP_ENDPOINT` and `uploads`' `S3_ENDPOINT` use `httpUrl()`; `optionalString` becomes `blankAsUndefined(...)`.
- Existing tests in `src/shared/lib/__tests__/env*.test.ts` move to `packages/env/src/__tests__/` unchanged in meaning; `src/__tests__/instrumentation.test.ts` keeps passing.
- `uploads` patch bump; `core` minor bump.

**Behaviours:**
- `httpUrl().safeParse("localhost:4318")` → failure; `"http://localhost:4318"` → success; `"ftp://x"` → failure.
- `blankAsUndefined(z.string().optional()).parse("   ")` → `undefined`; `"a"` → `"a"`.
- `allOrNone(["A","B"])` with only `A` set → one issue on `A`, message naming both and `missing: B`; none set or both set → no issue; a whitespace-only value counts as unset.
- `requiredForProvider("STORAGE_PROVIDER","s3",["S3_BUCKET"])` with `STORAGE_PROVIDER=s3` and no bucket → issue on `S3_BUCKET`; with `local` → none.
- `checkEnv` with `OTEL_EXPORTER_OTLP_ENDPOINT=localhost:4318` → issue on that variable (today: accepted).
- `formatEnvReport` output identical to today's for the same issues (D48 messages are a contract).
- Architecture: no file imports `@/shared/lib/env`.

**Mutations to kill:** `httpUrl` accepting any scheme; `blankAsUndefined` trimming only `""`; `allOrNone` passing when one of three is set; `requiredForProvider` ignoring the provider value.

### Task 3: `@gatojs/observability`

**Branch:** `feat/package-observability` (after Task 2)

**Files:**
- `packages/observability/` (`@gatojs/observability`, owned by `core`; dependencies `@opentelemetry/api`, `@opentelemetry/api-logs`).
- `createLogger(scope)` from today's `src/shared/lib/logger.ts` (with the minified-name fix); `src/shared/lib/logger.ts` becomes a one-line binding `export const logger = createLogger(project.slug)` or its imports move to the package (worker's choice, no behaviour change).
- `createTelemetry(serviceName)` with `withSpan(name, attributes, fn)`, `tracer`, `meter` (Ragen's `telemetry.ts`).
- `src/instrumentation.ts`: when `OTEL_EXPORTER_OTLP_ENDPOINT` is set, also register a trace exporter (`/v1/traces`); nothing without the endpoint. Optional `@prisma/instrumentation` only if it adds no work without the endpoint. New OTel packages follow the versions already in the lockfile (OpenTelemetry moves as a set; issue #65).

**Behaviours:**
- `withSpan` returns `fn`'s value, sets status OK and ends the span; when `fn` throws, it sets status ERROR with the message, records the exception, ends the span and rethrows the same error.
- A thrown non-`Error` value is recorded as `new Error(String(value))` and rethrown unchanged.
- `normalizeAttributes`: an `Error` with a string `name` → `<key>.type` equals that name (not `constructor.name`); an invalid `Date` → `"Invalid Date"`; a circular object → its `String()` form; `undefined`/`null` skipped.
- `register()` without the endpoint creates no exporter; with it, a log and a trace exporter pointing at `<endpoint>/v1/logs` and `<endpoint>/v1/traces` (trailing slash removed).

**Mutations to kill:** span not ended on error; error swallowed; `constructor.name` used; trailing slash kept.

### Task 4: `@gatojs/crypto` and the `encryption` module

**Branch:** `feat/module-encryption` (after Task 2)

**Files:**
- `packages/crypto/` (`@gatojs/crypto`, owned by the new module): Ragen's `envelope.ts` (AES-256-GCM, `base64(IV[12] ‖ ciphertext ‖ tag[16])`), `parseMasterKey` (64-char hex first, then base64 of exactly 32 bytes), `KeyProvider` interface, `LocalKeyProvider`, `probeEncryptionProvider`, `assertEncryptionAvailable`. No KMS providers in this task (spec 4.4 decision).
- Module `encryption`: `kit/modules/encryption.json` (version `0.1.0`, `files`: `packages/crypto/**`, `src/features/encryption/**`, `prisma/schema/encryption.prisma`), `src/features/encryption/module.ts`, `env.ts` (`ENCRYPTION_PROVIDER` = `local`, `ENCRYPTION_MASTER_KEY` required for `local` via `requiredForProvider`, rejected in production when equal to the `.env.example` value), a startup probe in the module's env/instrumentation seam, and the API `encryptForOrganization(organizationId, plaintext)` / `decryptForOrganization(organizationId, ciphertext)` with a per-organization data key (`OrganizationDataKey` model: `organizationId` unique, wrapped key, `createdAt`), created on first use. Queries go through the organization guard (the model has `organizationId`).
- `mutation-gate.json` `critical` += `packages/crypto/src/`, `src/features/encryption/services/`.
- Docs: `docs/17-encryption-module.md` (English, English file name), module list in `docs/12-moduly-kitu.md`, `.env.example` region via `wa generate`, the `assemble` matrix in `kit.yml` (`encryption` alone and in `all`).
- ADR-57 if a decision beyond the spec comes up (for example the data-key table design).

**Behaviours:**
- `decryptContent(<fixed vector from Ragen's envelope.test.ts>, <fixed key>)` → the fixed plaintext (format pinned by a vector, not by a round trip).
- `decryptContent` of a payload shorter than 28 bytes → throws with "expected at least 28 bytes"; a flipped ciphertext byte → throws (auth tag).
- `parseMasterKey` of 64 hex chars → 32 bytes; of base64 of 32 bytes → 32 bytes; of base64 of 48 bytes → throws with the generation hint; surrounding whitespace is trimmed.
- `encryptForOrganization(orgA, "x")` then `decryptForOrganization(orgA, …)` → `"x"`; `decryptForOrganization(orgB, <orgA ciphertext>)` → throws (different data key); two encryptions of the same plaintext differ (random IV).
- Isolation integration test with two organizations: orgA's data key row is never read with orgB's context.
- Without `ENCRYPTION_MASTER_KEY` and `ENCRYPTION_PROVIDER=local` → startup report names `ENCRYPTION_MASTER_KEY`.

**Mutations to kill:** IV length or tag length changed; hex check skipped; data key shared across organizations; probe passing with an unusable key.

### Task 5: `@gatojs/eslint-config`

**Branch:** `feat/package-eslint-config` (after Tasks 2–4)

- `packages/eslint-config/` (`@gatojs/eslint-config`, owned by `core`): `base` (Ragen's `eqeqeq`, `no-console` with tests exempt, `consistent-type-imports` on TS files, the ignore list including Playwright output) plus the kit's rules (`curly`, `no-nested-ternary`, the error-class-name rule) and `next` (eslint-config-next core-web-vitals + typescript). Ragen's relaxations (`no-explicit-any: off`, React Compiler rules as warnings) stay out.
- Root `eslint.config.mjs` and every package import it. Fix new findings in the same task, or list them in the report when a fix is out of scope.
- **Behaviours:** a fixture file with `==`, `console.log` outside tests, a nested ternary and `this.name = this.constructor.name` fails lint with those four rules; the same file in `__tests__/` only loses the `no-console` error.

### Task 6: Publish `create-gato-app` and `gato-cli`

**Branch:** `feat/publish-tools` (after Task 1)

- Move branch `patrykomiotek/create-gato-app` (`kit/create-gato-app`, 0.1.0) to `packages/create-gato-app` as a tool package (`kitOnly`), on top of Task 1.
- `.github/workflows/packages.yml` (kit-only), modelled on Ragen's `ragen-cli.yml` and `installer.yml`: pack both packages, install the tarballs, `gato --version` equals `package.json`, unknown command exits non-zero, `create-gato-app <tmp> --kit $GITHUB_WORKSPACE --yes --no-install --no-git` assembles a project, and the assembled project uses the packed `gato-cli` (spec `2026-11-21-gato-cli-design.md` §9, `--cli-source`).
- `.github/workflows/publish-packages.yml` (kit-only): on a tag `gato-cli@<v>` or `create-gato-app@<v>` set by a human, publish with `npm publish --provenance --access public` through npm trusted publishing (OIDC, no token secret). Document the one-time npm setup (trusted publisher for `webamigos/gatojs`, workflow file name) in `kit/CLAUDE.md`.
- The first publish of each name is done by Patryk by hand (`npm login`, `npm publish --access public` from the package directory), because trusted publishing can only be configured for a package that exists. The report lists the exact commands.
- Behaviours: as in the two smoke tests above; the published tarball of `gato-cli` contains only `dist/gato.mjs`, `README.md`, `LICENSE`, `NOTICE`, `package.json`.

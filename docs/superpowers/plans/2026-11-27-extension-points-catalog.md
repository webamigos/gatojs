# Task 18: `EXTENSION_POINTS.md` catalog, stale-key tests, `gato-extend` skill

Detailed plan for Task 18 of [the extensibility plan](2026-11-23-extensibility.md) (branch `feat/extension-points-catalog`). The parent plan's "Global constraints" apply.

## Decision: how the generator reads declarations

The CLI bundle (`.wa/bin/wa.mjs`, ~0.9 MB, committed into every project) does not contain the TypeScript compiler; bundling it would add ~9 MB to every project. So the catalog's labels and descriptions live in one hand-written JSON file per module, next to its declarations, and an architecture test compares that file with the code in both directions (parent plan, option 2; recorded in ADR-63).

- `src/features/<x>/extension-points.json`: the points owned by module `<x>`.
- `src/shared/lib/modules/extension-points.json`: core-hosted points (owner `app`, today only the slot `app.header.actions`).

### File format (both files)

```json
{
  "stability": "stable",
  "description": "Dashboard page and its sections",
  "nav": { "dashboard.home": { "stability": "stable", "description": "Dashboard link in the sidebar" } },
  "slots": { "dashboard.sections": { "stability": "stable", "description": "Server sections under the dashboard heading" } },
  "components": {},
  "events": {},
  "commands": {},
  "authPaths": {},
  "permissions": {}
}
```

- Every field is optional; an unknown field is an error. A point is `{ "stability": "stable" | "experimental", "description": string }`, both required, no other fields.
- `description`: 1–160 characters, no newline, no `|` (it goes into a Markdown table cell).
- Top-level `stability` and `description` describe the module row. A feature with `module.ts` and no file (or without those two fields) gets a module row with `experimental` and description `-`. The `app` file's top-level fields are not allowed (there is no `app` module row).
- An invalid file stops `generate` with an `Error` whose message starts with the repo-relative file path, e.g. `src/features/demo/extension-points.json: slots.demo.panel.stability: expected "stable" or "experimental"` (exact wording after the path is free, the path prefix is not).

## Generator (`packages/gato-cli`)

New file `packages/gato-cli/src/generate/extension-points.ts`:

```ts
export type Stability = "stable" | "experimental";
export type CatalogKind =
  | "modules" | "navItems" | "slots" | "components"
  | "events" | "commands" | "authPaths" | "permissions";
export type CatalogRow = { key: string; module: string; stability: Stability; description: string };
export type ExtensionPointCatalog = Record<CatalogKind, CatalogRow[]>;
export const CATALOG_KINDS: readonly CatalogKind[]; // the order above
export const APP_EXTENSION_POINTS_FILE = "src/shared/lib/modules/extension-points.json";
export const EXTENSION_POINTS_TS = "src/extension-points.generated.ts";
export const EXTENSION_POINTS_MD = "EXTENSION_POINTS.md";
export function parseExtensionPointsFile(file: string, text: string, owner: string): Partial<ExtensionPointCatalog> & { moduleRow?: Omit<CatalogRow, "key" | "module"> };
export async function readExtensionPoints(projectDir: string, features: { name: string; hasModuleTs: boolean }[]): Promise<ExtensionPointCatalog>;
export function renderExtensionPointsTs(catalog: ExtensionPointCatalog): string;
export function renderExtensionPointsMarkdown(catalog: ExtensionPointCatalog): string;
```

(`parseExtensionPointsFile`'s return shape is the implementer's choice; tests go through `readExtensionPoints` and the renderers.)

- File key → catalog kind: `nav` → `navItems`, the other names are equal.
- `readExtensionPoints`: for each feature, reads `src/features/<name>/extension-points.json` if present (owner = feature name), then the `app` file if present (owner `app`). Module rows: one per feature with `hasModuleTs`. Every list sorted by `key` with `compareCodePoint` (`packages/gato-cli/src/compare.ts`), ties by `module`. Points of a feature without `module.ts` are still listed.
- `generate()` writes both files every run (also when the catalog is empty). `GENERATED_FILES` in `packages/gato-cli/src/generate/index.ts` and `generatedFiles` in `kit/kit.json` gain `src/extension-points.generated.ts` and `EXTENSION_POINTS.md`.

### `src/extension-points.generated.ts` (exact shape)

```ts
// generated by GatoJS — do not edit. Run: npm run wa -- generate
export type ExtensionPointStability = "stable" | "experimental";

export interface ExtensionPoint {
  key: string;
  module: string;
  stability: ExtensionPointStability;
  description: string;
}

export const extensionPoints = {
  modules: [
    { key: "account", module: "account", stability: "stable", description: "Account page" },
  ],
  navItems: [],
  slots: [],
  components: [],
  events: [],
  commands: [],
  authPaths: [],
  permissions: [],
} as const satisfies Record<string, readonly ExtensionPoint[]>;

export type ModuleKey = "account";
export type NavItemId = never;
export type SlotId = never;
export type ComponentHandle = never;
export type EventName = never;
export type CommandKey = never;
export type PermissionKey = never;
```

- A non-empty list prints `  <kind>: [`, one row per line indented 4 spaces, then `  ],`; an empty list prints `  <kind>: [],`. String values are `JSON.stringify`-ed. A union of several keys is `"a" | "b"` on one line, in catalog order. The file ends with a newline.

### `EXTENSION_POINTS.md` (exact shape)

```md
<!-- generated by GatoJS — do not edit. Run: npm run wa -- generate -->
# Extension points

Change GatoJS behaviour through these keys, not by editing Gato files (skill: `.claude/skills/gato-extend/SKILL.md`). A `stable` key changes only with a `kitFormat` bump and a release note naming the old and new key; an `experimental` key can change in any release. Labels and descriptions live in each module's `extension-points.json`.

## Modules

Configure under `modules.<key>` in `src/gato.config.ts`.

| Key | Module | Label | Description |
| --- | --- | --- | --- |
| `account` | account | stable | Account page |

## Nav items

…
```

Sections in this order, each with its heading and one fixed sentence, then the table, or `_None._` when the list is empty:

| Heading | Sentence |
| --- | --- |
| `## Modules` | ``Configure under `modules.<key>` in `src/gato.config.ts`.`` |
| `## Nav items` | ``Reorder or hide under `modules.<module>.nav` in `src/gato.config.ts`.`` |
| `## Slots` | ``Contribute from `slots.ts` or `client-slots.ts`; reorder or remove contributions under `modules.<module>.slots`.`` |
| `## Component handles` | ``Replace or wrap from `components.ts` or under `modules.<module>.components`.`` |
| `## Events` | ``Subscribe from `subscribers.ts`; subscribers run after the operation succeeded.`` |
| `## Commands` | ``Add `before` hooks from `command-hooks.ts`.`` |
| `## Better-auth paths` | ``Not GatoJS commands: hook them with a `before` or `after` hook in your module's `auth.ts` plugin.`` |
| `## Permissions` | ``Check with `can(context, key)`; change default roles under `modules.<module>.permissions`.`` |

Blank line between heading, sentence, table/`_None._` and the next heading; the file ends with one newline. Rows: `` | `<key>` | <module> | <stability> | <description> | ``.

## App side

- `src/shared/lib/modules/gato-config.ts`: `defineGatoConfig(config: ProjectGatoConfig): GatoConfig`, where `ProjectGatoConfig` keys `modules` by `ModuleKey | "app"`, `nav` by `NavItemId`, `permissions` by `PermissionKey`, `slots` by `SlotId`, `components` by `ComponentHandle` (all from `@/extension-points.generated`, type-only imports). `GatoConfig` itself and `applyGatoConfig`, `gatoConfigProblems`, … keep their loose `Record<string, …>` types (tests use arbitrary module keys). A typo in `src/gato.config.ts` then fails `npm run typecheck`, as well as the import-time check.
- `scripts/lib/architecture/extension-points.ts`: `export async function findExtensionPointProblems(root: string): Promise<string[]>`; `src/__tests__/architecture/extension-points-exist.test.ts` runs it on fixture repos in a temp directory and on the repo (`toEqual([])`).

### What counts as "in code" (everything read from `root`)

Source files: `src/**/*.ts` and `src/**/*.tsx`, excluding `__tests__/` directories, `*.test.*`, `*.spec.*` and `*.generated.ts`.

| Kind | Declared / used in code |
| --- | --- |
| modules | feature directories with `src/features/<x>/module.ts` (key = directory name) |
| navItems | `id` of every `nav` item of each `module.ts` default export (items without `id` ignored) |
| slots | declared: `coreSlotDefinitions` exported by `src/shared/lib/modules/slots.ts` (owner `app`) and `slotDefinitions` exported by each `src/features/<x>/slots.ts`; rendered: `<Slot … id="x"` and `<ClientSlot … id="x"` JSX (attributes may span lines) and `visibleContributions(<first argument>, "x"` in source files |
| components | `overridable("x"` calls in source files |
| events | declared: keys of `coreEvents` exported by `src/shared/lib/events/core-events.ts` and of `events` exported by each `src/features/<x>/events.ts`; emitted: a string literal among the arguments of an `emitEvent(` call, a string in an `events: [ … ]` array in a file that calls `defineCommand(`, or `name: "x"` on the line after an `origin:` property (the emit objects of `src/shared/lib/auth/organization-events.ts`) |
| commands | `key: "x"` of the object passed to `defineCommand(` in source files |
| authPaths | values of `ORGANIZATION_EVENT_PATHS` exported by `src/shared/lib/auth/organization-events.ts` |
| permissions | keys of `permissions` of each `module.ts` default export |

Files are imported (TypeScript through Vitest) for the rows that say "exported"; the rest is a text scan. A missing file contributes nothing. The catalog is `extensionPoints` imported from `src/extension-points.generated.ts`; if that file is missing the only problem is `src/extension-points.generated.ts: missing; run npm run wa -- generate`.

### Problems (exact text; returned in kind order, then sorted by key with `localeCompare`-free code-point order, then by message)

Stale catalog key (`<module>` is the row's module):

| Kind | Message |
| --- | --- |
| modules | `<key>: no module (expected in src/features/<key>/module.ts)` |
| navItems | `<key>: no nav item (expected in src/features/<module>/module.ts)` |
| slots | `<key>: no defineSlot (expected in src/features/<module>/slots.ts)`; for module `app`: `(expected in src/shared/lib/modules/slots.ts)` |
| components | `<key>: no overridable (expected in src/features/<module>/)` |
| events | `<key>: no event declaration (expected in src/features/<module>/events.ts)`; for an event of module `auth`, `organizations` or `users` the path is `src/shared/lib/events/core-events.ts` |
| commands | `<key>: no defineCommand (expected in src/features/<module>/services/commands/)` |
| authPaths | `<key>: not in ORGANIZATION_EVENT_PATHS (expected in src/shared/lib/auth/organization-events.ts)` |
| permissions | `<key>: no permission (expected in src/features/<module>/module.ts)` |

Code key missing from the catalog: `<key>: missing from EXTENSION_POINTS.md (<file where it was found>)`; for slots that file is the declaring file, for handles and commands the file with the call, for events the declaring file, for modules, nav items and permissions `src/features/<x>/module.ts`, for auth paths `src/shared/lib/auth/organization-events.ts`.

Use without declaration and declaration without use:

- `<slot>: declared in <file> but never rendered` (declared, no render anywhere)
- `<slot>: rendered but not declared (<file with the render>)`
- `<event>: declared in <file> but never emitted`
- `<event>: emitted but not declared (<file with the emit>)`

Namespacing: every catalog row of kinds navItems, slots, components, events, commands, permissions whose key does not start with `<module>.` (with something after the dot): `<key>: must start with "<module>."`.

A problem is never a warning: the repo test asserts `toEqual([])`.

## Mutations to kill

- Catalog lists generated unsorted (any kind), or sorted by insertion order of features.
- A stale key reported as a warning / filtered out (the repo test or a fixture test passes with a stale row).
- One kind of key (events, commands, components, nav, permissions, authPaths, modules, slots) missing from the check in either direction.
- Test files counted as renders/uses.
- `_None._` dropped or sections reordered in the Markdown.
- Schema accepts a third stability value, an empty or multi-line description, or unknown fields.
- `generate` not writing one of the files or `GENERATED_FILES` missing one.

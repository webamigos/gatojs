# `wa update`: plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Komenda `wa update <wersja>` przenosi projekt (rdzeń i zainstalowane moduły kitu) z `kitVersion` na tag `v<wersja>`, scalając zmiany kitu trójstronnie z lokalnymi zmianami projektu.

**Architecture:** Nowy katalog `kit/cli/src/update/` z czystymi częściami: porównanie wersji, migawka wersji kitu (pliki po placeholderach), scalanie przez `git merge-file`, plan dla każdego pliku. `kit/cli/src/commands/update.ts` składa je w komendę (kontrole, zapis, cofanie, `generate`, `npm install`, podpowiedzi) i przekazuje pracę bundlowi wersji docelowej. `bin.ts` i `args.ts` dostają komendę.

**Tech Stack:** TypeScript, Node 22 (`node:child_process`, `node:fs/promises`), Zod 4, Vitest, Stryker, esbuild; `git` (`clone`, `merge-file`, `status`).

**Spec:** [docs/superpowers/specs/2026-11-03-wa-update-design.md](../specs/2026-11-03-wa-update-design.md). Wykonawca czyta spec razem z planem; numery § w zadaniach odnoszą się do specu.

## Review Focus

1. **Plik projektu równy hashowi, ale baza z tagu inna** (projekt założony z brudnego klonu). Oczekiwane: scalenie albo „do decyzji”, nigdy nadpisanie ani usunięcie, plus linia `Uwaga`. Test: Task 5.
2. **Konflikt w `package.json`** (projekt i kit zmieniły wersję tej samej zależności). Oczekiwane: markery w `package.json`, `npm install` i `generate` pominięte, kod 1. Test: Task 6.
3. **Plik w regionie `wa:*` zmieniony tylko w treści regionu po stronie projektu**, a kit zmienił linię poza regionem. Oczekiwane: zaktualizowany bez konfliktu, region odtworzony przez `generate`. Test: Task 5 i Task 6.
4. **Symlink w projekcie wskazujący poza projekt na ścieżce pliku kitu.** Oczekiwane: `Ścieżka poza projektem: <ścieżka>` przed jakimkolwiek zapisem. Test: Task 6.
5. **`--dry-run` na brudnym drzewie i z konfliktami.** Oczekiwane: plan wypisany, kod 0, projekt bajt w bajt bez zmian. Test: Task 6.

### Task 1: Argumenty i porównanie wersji

**Files:**
- Create: `kit/cli/src/update/version.ts`
- Modify: `kit/cli/src/args.ts` (nowe `parseUpdateArgs`)

- Test: `kit/cli/src/update/__tests__/version.test.ts`, `kit/cli/src/__tests__/args.test.ts`

**Interfaces:**
- Produces: `parseVersion(value: string): string` (zwraca wartość albo rzuca); `compareVersions(a: string, b: string): number` (ujemna, 0, dodatnia); `UpdateArgs = { version: string; kit: string | null; fromKit: string | null; dryRun: boolean; install: boolean }`; `parseUpdateArgs(argv: string[]): UpdateArgs`.

**Zachowania:**
- `parseVersion("0.2.0")` → `"0.2.0"`; `"1.10.3-rc.1"` → bez zmian.
- `parseVersion("v0.2.0")`, `"0.2"`, `""`, `"0.2.0.1"`, `"01.2.0"` → błąd `Nieprawidłowa wersja: <wartość>; podaj na przykład 0.2.0`.
- `compareVersions("0.10.0", "0.9.0")` > 0 (liczbowo, nie leksykalnie); `("1.0.0", "1.0.0")` = 0; `("1.0.0-rc.1", "1.0.0")` < 0; `("0.1.0", "0.2.0")` < 0.
- `test.prop`: `compareVersions(a, b) === -compareVersions(b, a)` (znak) i `compareVersions(a, a) === 0` dla wygenerowanych `x.y.z`.
- `parseUpdateArgs(["0.2.0"])` → `{ version: "0.2.0", kit: null, fromKit: null, dryRun: false, install: true }`.
- `["0.2.0", "--kit", "/k", "--dry-run", "--no-install", "--from-kit", "/c"]` → wszystkie pola ustawione.
- `[]` → `Podaj wersję kitu`; `["0.2.0", "x"]` → `Nieoczekiwany argument: x`; `["0.2.0", "--kit="]` → `Opcja --kit wymaga wartości`; `["0.2.0", "--force"]` → `Nieznana opcja: --force`; `["v1"]` → błąd `parseVersion`.

**Mutacje do zabicia:** porównanie wersji jako napisów; prerelease równy wersji bez sufiksu; zgoda na prefiks `v`; zgoda na zero wiodące; `install` niezależne od `--no-install`.

- [ ] Testy (test-writer), czerwony przebieg: `npx vitest run src/update src/__tests__/args.test.ts` w `kit/cli`.
- [ ] Implementacja: `parseUpdateArgs` przez istniejące `parseOptions`, `optionalValue`, `assertMaxPositionals`; wzorzec wersji `^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)(-[0-9A-Za-z.-]+)?$`; prerelease porównywany jak w semver (brak sufiksu > sufiks, identyfikatory po kropkach, liczbowe liczbowo).

### Task 4: Scalanie trójstronne

**Files:**
- Create: `kit/cli/src/update/merge.ts`
- Test: `kit/cli/src/update/__tests__/merge.test.ts`

**Interfaces:**
- Consumes: `stripRegions` z `kit/cli/src/assemble/hash.ts`, `REGION_FILES`.
- Produces:
  ```ts
  export type MergeResult = { content: Buffer; conflicts: number } | { binary: true };
  export async function mergeFile(input: {
    path: string;
    base: Buffer;
    ours: Buffer;
    theirs: Buffer;
    labels: { ours: string; base: string; theirs: string };
  }): Promise<MergeResult>;
  ```
  Bajt `0` w którejkolwiek stronie → `{ binary: true }` bez wołania gita. Dla `REGION_FILES` wszystkie trzy strony przechodzą przez `stripRegions` przed scaleniem. Scalenie: trzy pliki w `mkdtemp`, `git merge-file -p --diff3 -L <ours> -L <base> -L <theirs> <ours> <base> <theirs>`, wynik ze stdout; kod 0 → 0 konfliktów, kod 1–127 → tyle konfliktów, inny kod albo sygnał → błąd `git merge-file: <stderr>`. Katalog tymczasowy usuwany zawsze.

**Zachowania:**
- Zmiana w linii 2 po stronie projektu i w linii 10 po stronie kitu → `conflicts: 0`, treść z obiema zmianami.
- Ta sama linia zmieniona różnie → `conflicts: 1`, treść zawiera `<<<<<<< projekt`, `||||||| v0.1.0`, `=======`, `>>>>>>> v0.2.0`.
- Dwie niezależne kolizje → `conflicts: 2`.
- `.env.example`: projekt ma inną treść regionu `wa:modules`, kit dodał linię poza regionem → `conflicts: 0`, region pusty między markerami, nowa linia obecna.
- `Buffer.from([0, 1, 2])` jako `theirs` → `{ binary: true }`.
- Po wywołaniu (także po błędzie) w katalogu tymczasowym systemu nie zostaje katalog `wa-merge-*`.

**Mutacje do zabicia:** brak `stripRegions`; kod wyjścia 1 traktowany jak sukces; zamiana kolejności `ours`/`theirs`; brak sprzątania katalogu.

- [ ] Testy, czerwony przebieg.
- [ ] Implementacja (`execFile` z `promisify`; odczyt kodu z błędu `execFile`, stdout także przy kodzie > 0).
- [ ] Zielony przebieg, mutacje, commit `feat(cli): three-way merge of kit files`.

### Task 5: Plan aktualizacji

**Files:**
- Create: `kit/cli/src/update/plan.ts`
- Test: `kit/cli/src/update/__tests__/plan.test.ts`

**Interfaces:**
- Consumes: `KitSnapshot` (Task 3), `mergeFile` (Task 4), `fileHash` z `assemble/hash.ts`.
- Produces:
  ```ts
  export type PlanAction =
    | "zaktualizowano" | "scalono" | "dodano" | "usunięto" | "konflikt" | "do decyzji";
  export type PlannedFile = {
    path: string;
    action: PlanAction;
    reason: string | null;
    content: Buffer | null;
    mode: number | null;
  };
  export type UpdatePlan = { files: PlannedFile[]; mismatchedBase: string[] };
  export async function planUpdate(input: {
    base: KitSnapshot;
    target: KitSnapshot;
    recordedHashes: Record<string, string>;
    readProject: (path: string) => Promise<Buffer | null>;
  }): Promise<UpdatePlan>;
  ```
  `files` posortowane `compareCodePoint` po `path`, tylko pozycje ze zmianą (tabela § 6 bez wierszy „bez zmian”). `content`: treść do zapisu (`null` przy „usunięto”, „do decyzji” i konflikcie bez markerów). `mode`: bity z `target` dla „zaktualizowano”, „scalono”, „dodano”, konfliktu z markerami; inaczej `null`. Etykiety scalenia: `projekt`, `v<base.version>`, `v<target.version>`. Równość treści: `fileHash(path, content, { managedFiles: [] })`.
  `reason` (dokładne napisy): `"usunięty w projekcie, zmieniony w kicie"`, `"zmieniony w projekcie, usunięty w kicie"`, `"plik projektu na ścieżce nowego pliku kitu"`, `"plik binarny zmieniony w projekcie i w kicie"`; inaczej `null`.
  „Projekt równy bazie” (§ 6): `hash(projekt) === hash(baza)` i — dla ścieżki z wpisem w `recordedHashes` innym niż `managed` — `recordedHashes[path] === hash(baza)`. Ścieżka, dla której `hash(projekt) === recordedHashes[path] !== hash(baza)`, trafia do `mismatchedBase` i idzie ścieżką „inny niż baza”.

**Zachowania** (każdy wiersz tabeli § 6 osobnym testem, snapshoty budowane w pamięci, `readProject` z mapy):
- baza = kit, projekt dowolny → brak pozycji.
- kit ≠ baza, projekt = baza (i hash zapisany = baza) → `zaktualizowano`, `content` = treść kitu, `mode` z kitu.
- kit ≠ baza, projekt = kit → brak pozycji.
- kit ≠ baza, projekt ≠ obu, bez kolizji → `scalono`; z kolizją → `konflikt`, `content` z markerami.
- kit ≠ baza, projekt brak → `do decyzji`, `"usunięty w projekcie, zmieniony w kicie"`, `content: null`.
- kit brak, projekt = baza → `usunięto`; projekt ≠ baza → `do decyzji`, `"zmieniony w projekcie, usunięty w kicie"`; projekt brak → brak pozycji.
- baza brak, kit jest, projekt brak → `dodano`; projekt = kit → brak; projekt ≠ kit → `konflikt`, `"plik projektu na ścieżce nowego pliku kitu"`, `content: null`.
- Binarny zmieniony po obu stronach → `konflikt`, `"plik binarny zmieniony w projekcie i w kicie"`, `content: null`.
- Plik z regionami: projekt różni się od bazy tylko treścią regionu, kit zmienił linię poza regionem → `zaktualizowano`.
- Baza niezgodna z hashem: projekt = hash zapisany ≠ baza, kit ≠ baza → `scalono` albo `konflikt` (nie `zaktualizowano`), ścieżka w `mismatchedBase`; to samo przy kicie bez pliku → `do decyzji`, nie `usunięto`.
- `package.json` (wpis `managed`): projekt = baza → `zaktualizowano`; projekt z własnym skryptem, kit podbił zależność → `scalono`.
- Kolejność `files` alfabetyczna niezależnie od kolejności map.

**Mutacje do zabicia:** usunięcie pliku zmienionego w projekcie; nadpisanie pliku projektu na ścieżce nowego pliku kitu; pominięcie warunku hasha zapisanego; `mode` z bazy zamiast z kitu; pozycja dla pliku bez zmian w kicie; przywrócenie pliku usuniętego w projekcie.

- [ ] Testy, czerwony przebieg.
- [ ] Implementacja: zbiór ścieżek = klucze `base.files` ∪ `target.files`; jedna funkcja decyzji na ścieżkę według tabeli.
- [ ] Zielony przebieg, mutacje, commit `feat(cli): plan kit update per file`.

**Komunikaty i wyjście** (stdout przez `log`):
- równa wersja: `Projekt ma już wa-kit <wersja>`, `exitCode: 0`, nic nie zapisane;
- niższa: błąd `Projekt ma wa-kit <bieżąca>, nowszą niż <wersja>; wa update nie obniża wersji`;
- brak gita: `<katalog> nie jest repozytorium git; wa update wymaga gita, żeby dało się cofnąć zmiany`;
- brudne drzewo: `Niezacommitowane zmiany w projekcie; zrób commit albo stash przed wa update`;
- nagłówek: `Aktualizacja wa-kit <stara> → <nowa>`, przy `--dry-run`: `Plan aktualizacji wa-kit <stara> → <nowa> (bez zmian w projekcie)`;
- linia pozycji: `  <akcja> <ścieżka>` (akcja dopełniona spacjami do szerokości najdłuższej, `do decyzji`), z `reason`: `  <akcja> <ścieżka> (<reason>)`; kolejność akcji: zaktualizowano, scalono, dodano, usunięto, konflikt, do decyzji; w każdej alfabetycznie;
- brak pozycji: `  bez zmian w plikach`;
- `mismatchedBase` niepuste: `Uwaga: <n> plików różni się od v<stara> z tagu; potraktowano je jak zmienione w projekcie`;
